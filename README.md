# 100マス計算（GIGAスクール構想対応版）

GIGAスクール構想で導入された端末（ChromebookやiPadなど）で、子どもたちが快適に計算練習に取り組めるように設計された「完全スタンドアロン」のデジタル100マス計算アプリです。

学校のネットワーク環境（フィルタリングや回線速度）に左右されず、ブラウザを開いた瞬間にサクサク動くことを最優先に開発されました。

## ✨ 主な機能

*   **💻 爆速・完全オフライン動作** 外部データベースや複雑なバックエンドサーバーを必要とせず、GitHub Pagesとブラウザの機能だけで完結して動作します。
    
*   **📝 3つの入力インターフェース**
    
    *   **AI手書き入力:** TensorFlow.jsを活用し、画面に直接数字を書いて入力できます（独自モデルをローカルで読み込み）。
        
    *   **ソフトウェアテンキー:** タッチパネルで押しやすい大型ボタンによる入力。
        
    *   **物理キーボード:** 十字キーとEnterキーによる高速なタイピング入力にも対応。
        
*   **⚡ 自動採点（すぐ判定）＆ 自動進行** 正解を入力した瞬間に「ピンポン！」と音が鳴り、自動で次のマスへ移動。間違えた場合は入力が自動リセットされ、思考のテンポを止めません。
    
*   **📊 成長が見える記録機能** ブラウザのLocalStorageを利用し、各計算モードの「ベストタイム」と「直近20回の記録」を自動的に保存・表示します。

*   **🎯 「一発で正解できた率」がわかる** 記録画面では、タイムだけでなく **初回正答率**（1回目の解答で正解できた割合）と、**よく間違えた計算**の一覧を表示します。「正解するまで次に進めない」設計では正解数が常に満点になるため、実力の変化はこちらの指標に表れます。割合は解いた問題数（`attempted`）を分母とするので、途中でやめても率がゆがみません。

*   **🚪 とちゅうでやめた記録も残る** プレイ中の「やめる」ボタンから中断でき、そこまでの取り組みも学習ログに記録されます（中断は「難しすぎる／量が多すぎる」という大切なサインのため、捨てずに残します）。タブを離れたまま5分戻らなかった場合も中断として記録し、その際は**離れた時刻で締める**ため、待っていた時間は学習時間に加算されません。Chromebookのメモリ不足などでタブが破棄された場合も、`pagehide` で記録を確定するため取り組みが失われません。

*   **📱 PWA対応（アプリとしてインストール可能）** ChromeやEdgeのアドレスバーに表示される「インストール」ボタン（またはメニューの「アプリをインストール」）から、ホーム画面・デスクトップにアプリとして追加できます。Service Workerにより2回目以降はオフラインでも起動し、手書き認識モデルもキャッシュされます。

*   **⌨️ 端末のキーボード（Gboardなど）が出てこない** 手書き入力またはボタン入力を使う設定のときは、マスをタップしても端末内蔵のソフトウェアキーボードが表示されません。画面の半分が隠れて手書き欄やテンキーが押せなくなる、キーボードから直接数字を打たれてしまう、といったことが起きません（`inputmode="none"` はiPadOSが未対応でAndroidでも無視されることがあるため、`readonly` を併用して確実に抑止しています。物理キーボードからの数字入力・BackSpaceはアプリ側で受け取るので、これまでどおり使えます）。

*   **🔍 いまの計算がひと目でわかる表示** プレイ中は画面上部に「8 + 9 = ?」のように現在解いている計算と残り問題数が常に表示されます。手書き欄やテンキーのすぐ上に出るので、視線を動かさずに何の計算をしているかがわかります。

*   **🖥️ どんな端末でもマス全体が見える** 画面幅に合わせてマスの大きさを自動調整し、スマートフォンでも100マス全体が横スクロールなしで一覧できます。

*   **📺 提示モード（電子黒板・一斉授業）** ヘッダーの「⤢」を押すと、文字とマスが大きくなり全画面表示になります。3840×2160 の電子黒板では 1マス 104px・数字 52px まで拡大し、教室のうしろの席からも読めます（ふつうの表示では 1マス 56px・数字 23.5px）。Esc またはもう一度押すと戻ります。入力ツール（手書き・テンキー）を表の横に広げるのは、横に並ぶ幅（1024px 以上）のときだけです。スマホやタブレットの縦向きでは入力ツールが表の下に回り込むため、提示モードでも画面の幅いっぱいのまま（実測: 幅 626px で手書き欄 274px・テンキー1つ 184px）で、指で押しやすい大きさを保ちます。児童名・出席番号を扱わないアプリのため、提示モードで伏せる情報はありません。

*   **🖨️ 白紙のプリントとして刷れる** 「スタート！」の前に印刷すると、16mm角のマスだけが A4 縦1ページに出ます。ボタン・メニュー・手書き入力の枠は紙には出ません。

*   **🟢 正誤を色だけで伝えない** 正解は実線の枠、まちがいは破線の枠でも区別します。色の見分けがつきにくい児童にも、Windows のハイコントラストモード（面の色が消える）でも、同じ手がかりが残ります。
    

## 📚 学習ログ（`study.v1`）

このアプリは、GIGA山 学習アプリ群の共通スキーマ **`study.v1`** に従って学習ログを端末内に保存します。

*   **出力するスキーマ版:** `study.v1`
*   **`appId`:** `square100`
*   **保存先:** `localStorage` のキー **`study.records.v1`**（JSON 配列 / 最大500件）
*   **送信は一切行いません。** 保存のみです。外部への送信は、同一オリジンに置く別ページ（送信ページ）が担当します。
*   **児童を識別する情報は含みません。** 氏名・出席番号・メールアドレス・端末情報は記録しません。

> ⚠️ `study.records.v1` は複数アプリ共通の学習ログです。このアプリ専用のキーではないため、
> リセット処理やクリーンアップの対象に含めないでください。
> （このアプリ固有のデータは `giga_calc_settings_v4` / `giga_calc_records_v4` です。`localStorage.clear()` は使用しません。）

### 記録している内容

| 層 | 内容 |
|---|---|
| コア層 | `mode`（`add` / `sub` / `mul`）、`unit.id`（`add-100` のようにモード＋マス数）、`startedAt`（ISO 8601）、`elapsedMs`、`activeMs`、`status`（`completed` / `aborted`）、`summary.count` / `attempted` / `firstTryCorrect` / `correct` |
| 設問層 `items` | `q`（`8+9` のような設問ID）、`ok`、`firstTry`、`tries`、`ms`、`wrong`（誤答した数字） |
| 拡張層 `ext` | `autoScore`（自動採点か）、`input`（`handwriting` / `numpad` / `mixed` / `keyboard`）、`cells`、`bestMs`（記録がなければ `null`）、`wrongItems`（初回誤答した式・最大100件） |

`ext.input` と `ext.autoScore` は必須扱いです。入力方法が変わればタイムが大きく変わり、自動採点では正解数が常に満点になるため、
この2つがないと `elapsedMs` や `correct` の比較が成立しません。

設問IDは式そのもの（`8+9` / `13-9` / `8*9`）を用います。行の値は重複しうるため、**同じ `q` が1レコード内に複数現れます**。
集計側は同一 `q` を別々の試行として扱ってください（`q` をキーにした上書き集計は不可）。

一度も手をつけていない問題は `attempted` / `firstTryCorrect` / `items` のいずれからも除外します。
未着手数は `count - attempted` で判ります。`attempted` は常に `items` の要素数と一致します。

### 中断レコードの扱い

| 原則 | 実装 |
|---|---|
| 離脱時刻で締める | タブ離脱による中断は、離れた瞬間の経過時間で `elapsedMs` / `endedAt` を確定する |
| 空レコードは保存しない | 1問も解答していない中断は記録しない |
| 復帰時は新規レコード | 中断済みレコードに追記せず、**残りのマスだけ**を受け持つ新しいレコードを始める |

中断は次の3経路で記録します。

| 経路 | 動作 |
|---|---|
| 「やめる」ボタン | その場で `aborted` として確定 |
| タブ非表示のまま5分 | 離れた時刻で `aborted` として確定（5分より短くしないこと） |
| `pagehide` | 確定してから離脱。Chromebook はメモリ不足やスリープでタブごと破棄されるため、5分タイマーだけではタイマーごと消えて記録が失われる |

`pagehide` の後 bfcache から復帰した場合は、そのとき**まだ解けていないマスだけ**を `count` とする新しいレコードを開始します。
このとき `unit.id` と `ext.cells` は盤面の大きさ（`add-100` / `100`）のまま変わらないため、過去データとの接続は切れません。
盤面の途中から始まったレコードのタイムはベストタイム（`ext.bestMs`）の対象外です。

`beforeunload` は使いません。モバイルおよび bfcache 経路で発火しないことがあり、タブ破棄を取りこぼすためです。

### 実装ファイル（3層構成）

| ファイル | 役割 |
|---|---|
| `src/studyLog.js` | 共通の保存モジュール（`saveStudyRecord`）。**全アプリで同一ロジックとすること**。ESM 形態 / ロジック版 **1.1** |
| `src/studySession.js` | このアプリ固有のレコード組み立て（`study.v1` §3.6 の定義） |
| `src/studyStats.js` | このアプリ用の読み出し・集計（記録画面の表示に使用。読み出し専用） |

## 🛠️ 技術スタック

*   **フロントエンド:** React 18 + Vite
    
*   **スタイリング:** Tailwind CSS
    
*   **PWA:** vite-plugin-pwa（`injectManifest`）+ **自前の `src/sw.js`**
    
*   **アイコン:** Lucide React（SVG。画像ファイルを持たない）
    
*   **AI・機械学習:** TensorFlow.js（手書き数字認識 / `model.json` を使用）。**CDN からは読まず、npm で版を固定して自己ホストしている**
    
*   **音声:** Web Audio API (外部音声ファイル不要の動的シンセサイザー)
    
*   **ホスティング:** GitHub Pages

## 🛠️ 開発

```bash
npm ci
npm run dev        # 開発サーバー
npm run build      # 本番ビルド（dist/）
npm run check              # GIGA Standard v5 品質ゲート
npm run check -- --self-test   # 検査そのものが動いているかを確かめる
```

`npm run check` はビルド成果物（先読みキャッシュの量など）も見るため、
**`npm run build` のあとに走らせる。** CI（`.github/workflows/ci.yml`）は
`pull_request` と `push` の両方で、build → check → 自己テストの順に走る。

### リリース手順

1. `src/**` を直す
2. **`package.json` の `version` と `src/sw.js` の `APP_VERSION` を両方上げる**
   （食い違うと `npm run check` が止める）
3. `npm run build && npm run check`
4. `main` へマージすると `.github/workflows/deploy.yml` が GitHub Pages へ公開する

## 🚀 デプロイ（公開）方法

`main` への push で `.github/workflows/deploy.yml` が動き、
`npm run build` の結果（`dist/`）を GitHub Pages へ公開します。

リポジトリの `Settings` > `Pages` で、`Build and deployment` の `Source` を
**`GitHub Actions`** にしておいてください（`Deploy from a branch` ではありません）。


## 💡 使い方（児童向け）

1.  アプリを開いたら、「計算（たし算・引き算・かけ算）」と「問題数（10〜100問）」を選びます。
    
2.  「スタート！」ボタンを押すとタイマーが動きます。
    
3.  空いているマスに答えを入力します。
    
    *   「設定」ボタンから、入力方法（手書き・ボタン）や、入力エリアの左右の配置を変更できます。
        
4.  全部のマスを埋めるとクリア！タイムが記録されます。
    
5.  とちゅうでやめたいときは「やめる」ボタンを押します（そこまでの記録は残ります）。

6.  右上の「グラフ」ボタンから、これまでの自分の成長（記録・初回正答率・にがてな計算）を確認できます。
    

## 🔒 設計上まもっていること（GIGA Standard v5）

学校のネットワークと端末を前提に、次を守っています。実測値は [AUDIT.md](AUDIT.md) にあります。

| 何を | なぜ |
|---|---|
| **実行コードを CDN から取らない**（0バイト） | 学校のフィルタリングで `cdn.jsdelivr.net` などが塞がれると、アプリが起動しない・機能が丸ごと死ぬ。しかも原因がアプリの外にあるため先生が調べても分からない |
| **CSP を入れている**（`script-src 'self'`） | インラインの `<script>` と `onclick=` は使わない。インストールの合図の捕捉も `install-hook.js` に切り出してある |
| **Service Worker は自アプリのキャッシュしか消さない** | `gigayama.github.io` は数十個のアプリが同一オリジンを共有している。`caches.keys()` の全削除は他アプリをオフラインで起動できなくする |
| **更新は押すまで切り替えない** | 計算の途中で入れ替わると、打ちかけの答えも計測中のタイムも消える |
| **`localStorage.clear()` を使わない** | `study.records.v1` は他アプリと共有している学習ログ。このアプリのリセット対象に含めてはならない |
| **TensorFlow.js を先読みキャッシュに入れない** | 先読みが1MBを超えると、校内 Wi-Fi で40人が同時に開いたときの初回表示が止まる。手書きを使った端末だけが実行時に取り込む |
| **拡大を禁止しない** | 誤ズーム防止より、見えづらい子が拡大できない害のほうが大きい |
| **ふりがな（`rt`）の色を決め打ちしない** | 色のついたボタンの上でふりがなが読めなくなる。ふりがなが要るのは低学年の児童で、いちばん読めなくて困る人がいちばん読めない形になる |
| **`overflow-x: auto` を `@media print` で戻す** | 画面では横スクロールになるが、紙にはスクロールが無いのではみ出した分は切り取られる。実測で 100マスの 10 列目が 3.5mm 切れていた |
| **forced-colors の受けを「対」で書く** | ハイコントラストでは面の色が両方とも消える。正解にだけ枠を足すと、まちがいが未回答とまったく同じ見た目になる |
| **提示モードを用意する** | 4K を 65〜75インチで遠くから見る電子黒板では、通常サイズの文字が読めない。文字だけ大きくしても本文幅の上限（`max-w-6xl`）でマスは大きくならないため、上限も外す |
